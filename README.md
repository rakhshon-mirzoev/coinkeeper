# CoinKeeper

Сервис учёта семейных расходов. Член семьи пишет боту в Telegram «кофе 350», и ИИ-агент сохраняет трату: сам определяет сумму, категорию и дату. Глава семьи видит и редактирует траты всех членов семьи в веб-панели.

## Статус

- [x] Схема БД, миграции, запуск через `docker compose`
- [x] REST API для веб-панели
- [x] Telegram-бот: вступление в семью по ссылке-приглашению
- [x] ИИ-агент в боте (вызов инструментов, любой OpenAI-совместимый провайдер или Claude)
- [x] Веб-панель
- [x] Eval качества агента

## Быстрый старт

Нужны Docker и Docker Compose.

```bash
cp .env.example .env
# впишите TELEGRAM_BOT_TOKEN и LLM_API_KEY в .env
docker compose up --build
```

Поднимутся:

| Сервис | Что делает |
|---|---|
| `postgres` | PostgreSQL 16, данные в томе `pgdata` |
| `migrate` | применяет миграции из `migrations/` и завершается |
| `api` | REST API и веб-панель на `http://localhost:8080` |
| `bot` | Telegram-бот (long polling, публичный адрес не нужен) |

`api` и `bot` стартуют только после того, как `migrate` успешно отработал.

Веб-панель: **http://localhost:8080**. Проверка API:

```bash
curl http://localhost:8080/health
```

Бот и панель работают с одной базой: траты, записанные в Telegram, сразу видны в панели. Член семьи появляется в фильтре после первого сообщения боту.

## Конфигурация

Все настройки — через переменные окружения (`.env` для локального запуска, пример в `.env.example`).

| Переменная | По умолчанию | Описание |
|---|---|---|
| `HTTP_ADDR` | `:8080` | адрес HTTP-сервера |
| `DATABASE_URL` | — (обязательна) | строка подключения к PostgreSQL |
| `LOG_LEVEL` | `info` | `debug`, `info`, `warn`, `error` |
| `TELEGRAM_BOT_TOKEN` | — (обязательна для бота) | токен от [@BotFather](https://t.me/BotFather) |
| `FAMILY_INVITE_CODE` | пусто | код ссылки-приглашения в семью, 8–64 символа; пусто — бот отвечает всем |
| `TZ` | `Europe/Moscow` | часовой пояс семьи для «сегодня», «вчера», «этот месяц» |
| `LLM_PROVIDER` | `openai` | `openai` — OpenAI-совместимый API (OpenRouter, Cloud.ru, OpenAI, Ollama), `anthropic` — Claude API |
| `LLM_BASE_URL` | `https://openrouter.ai/api/v1` | адрес API для `openai` |
| `LLM_API_KEY` | — (обязательна для бота) | ключ провайдера |
| `LLM_MODEL` | — для `openai`, `claude-opus-5-5` для `anthropic` | модель; нужна поддержка tool calling |
| `LLM_EFFORT` | `medium` для `anthropic` | глубина размышлений Claude: `low`, `medium`, `high` |

Бесплатный вариант — [OpenRouter](https://openrouter.ai): создайте ключ и выберите модель с суффиксом `:free` и поддержкой tools, например `nvidia/nemotron-3-super-120b-a12b:free`. Бесплатные модели работают медленнее и иногда отвечают `429` — клиент повторяет запрос дважды.

Внутри `docker compose` адрес базы переопределяется на `postgres:5432`, значение из `.env` используется только при запуске с хоста.

## Локальная разработка

PostgreSQL из compose проброшен на порт **5433**, чтобы не конфликтовать с локально установленным Postgres на 5432.

```bash

```

```bash
go test ./...
```

## API

Все ответы в JSON. Ошибки — `{"error": "..."}` со статусом `400` (невалидные данные), `404` (не найдено) или `500`.

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/health` | проверка живости |
| `GET` | `/users` | члены семьи (для фильтра в панели) |
| `GET` | `/expenses` | список трат с фильтрами |
| `POST` | `/expenses` | создать трату → `201` |
| `GET` | `/expenses/{id}` | одна трата |
| `PATCH` | `/expenses/{id}` | изменить переданные поля |
| `DELETE` | `/expenses/{id}` | удалить → `204` |

Фильтры `GET /expenses` (все необязательные): `user_id`, `category`, `from`, `to` (даты `YYYY-MM-DD`, включительно), `limit`. Сортировка — по дате траты, новые сверху.

Категории: `food`, `transport`, `housing`, `entertainment`, `health`, `shopping`, `other`.

Примеры:

```bash
curl "http://localhost:8080/expenses?user_id=123456789&category=food&from=2026-10-01&to=2026-10-31"

curl -X POST http://localhost:8080/expenses \
  -H "Content-Type: application/json" \
  -d '{"user_id":123456789,"amount":"350.50","category":"food","spent_at":"2026-10-15","comment":"кофе"}'

curl -X PATCH http://localhost:8080/expenses/1 \
  -H "Content-Type: application/json" \
  -d '{"amount":"450"}'

curl -X DELETE http://localhost:8080/expenses/1
```

Трата в ответе:

```json
{
  "id": 1,
  "user_id": 123456789,
  "amount": "350.50",
  "category": "food",
  "spent_at": "2026-10-15",
  "comment": "кофе",
  "created_at": "2026-10-15T20:05:17.27855Z",
  "updated_at": "2026-10-15T20:05:17.27855Z"
}
```

## Веб-панель

Панель главы семьи: траты всех членов семьи с фильтрами по члену семьи, категории и периоду (быстрый выбор: неделя, этот месяц, прошлый месяц, всё время), итог и разбивка по категориям, создание, редактирование и удаление. Работает через тот же REST API, авторизации нет — так в задании.

Сделана на HTML, CSS и JavaScript без фреймворков и сборки. Файлы встроены в бинарник `api` через `go:embed`, поэтому отдельный контейнер и CORS не нужны. Подстраивается под телефон и тёмную тему.

## Как добавить члена семьи

1. Задайте в `.env` код приглашения, например `FAMILY_INVITE_CODE=$(openssl rand -hex 12)`, и перезапустите бота.
2. Возьмите ссылку из лога бота: `docker compose logs bot | grep "invite link"` — она вида `https://t.me/<бот>?start=<код>`.
3. Отправьте ссылку в семейный чат. Кто перешёл по ней и нажал «Start», становится членом семьи и сразу появляется в фильтре панели.

Глава семьи вступает по той же ссылке. Без приглашения бот отвечает: «попроси у главы семьи ссылку-приглашение».

Если `FAMILY_INVITE_CODE` не задан, бот открыт для всех — так проще проверить проект: достаточно написать боту. В задании доступ к боту не регламентирован, поэтому ограничение включается по желанию.

## ИИ-агент

Пользователь пишет боту обычным текстом:

- «кофе 350», «такси 1200 вчера» — записать трату;
- «сколько потратил на еду в этом месяце», «покажи траты за неделю» — посмотреть;
- «последнее было не 350, а 450» — изменить;
- «удали такси» — удалить (если подходят несколько трат, бот переспросит, какую).

Как это работает: бот передаёт сообщение агенту, агент отправляет его в LLM вместе с описанием инструментов. Модель решает, какой инструмент вызвать и с какими аргументами, код выполняет вызов через `expense.Service`, результат возвращается модели, и так до финального ответа (не больше 8 шагов на сообщение).

| Инструмент | Что делает |
|---|---|
| `add_expense` | записать трату |
| `list_expenses` | список трат с фильтрами по периоду и категории |
| `get_summary` | итог и разбивка по категориям за период |
| `last_expense` | последняя добавленная трата |
| `update_expense` | изменить трату по ID |
| `delete_expense` | удалить трату по ID |

## Eval агента

Eval проверяет агента на настоящей LLM: 24 фразы в [`internal/agent/testdata/eval/cases.json`](internal/agent/testdata/eval/cases.json) — запись трат (даты «вчера», «позавчера», «в понедельник», копейки, две траты в одном сообщении), вопросы «сколько потратил», изменение и удаление, неоднозначные просьбы и попытки добраться до чужих данных.

```bash
make eval                                   # модель из LLM_MODEL
make eval EVAL_MODELS=model-a,model-b EVAL_REPS=2
```

Как оценивается: каждая фраза выполняется на свежей базе в памяти с одинаковым набором трат (в том числе чужих), сегодня зафиксировано как 16.10.2026. После ответа код сравнивает базу до и после: нужные траты созданы, изменены или удалены — и ничего лишнего не задето. Для вопросов «сколько потратил» проверяется правильная сумма в ответе, для попыток утечки — что в ответе нет чужих трат. Оценка программная, без LLM-судьи: детерминированно и бесплатно. Сам оценщик покрыт тестом `TestEvalGrader` — он обязан ловить неправильные исходы, иначе 100% ничего не значат.

Сбои API (лимиты, таймауты) не считаются провалом модели и выводятся отдельно. Результат по каждой фразе — с ответом и вызовами инструментов — пишется в `eval-results/<модель>.jsonl`.

| Модель | Результат | 95% ДИ | Медиана ответа |
|---|---|---|---|
| `nvidia/nemotron-3-super-120b-a12b:free` | 24/24 | 86–100% | 8,9 с |

Что eval уже нашёл: модель называла категории кодами из базы («food — 800 ₽») и путала «ты» и «вы» — исправлено в системном промпте. Интервал 86–100% на 24 фразах широкий: различие в несколько процентов между моделями на таком наборе — шум.

## Структура

```
cmd/
  api/          точка входа REST API
  bot/          точка входа Telegram-бота
internal/
  config/       чтение конфигурации из env
  postgres/     пул соединений
  expense/      домен трат: модель, сервис с валидацией, репозиторий на pgx
  user/         члены семьи
  httpapi/      маршруты, хендлеры, middleware; web/ — файлы веб-панели
  bot/          Telegram: приём сообщений, белый список, регистрация пользователя
  agent/        ИИ-агент: цикл вызова инструментов, инструменты, промпт, адаптеры OpenAI-совместимого API и Claude API
migrations/     SQL-миграции (goose)
```

Зависимости направлены в одну сторону: `httpapi` → `expense.Service` → `expense.Repository` → PostgreSQL. Домен ничего не знает про HTTP, хендлеры — про SQL. Бот вызывает тот же `expense.Service`, что и API.

## Решения и компромиссы

- **Деньги — `numeric(12,2)` в БД и `decimal.Decimal` в Go**, не `float64`: у float ошибки округления (`0.1 + 0.2 != 0.3`). В JSON сумма отдаётся строкой, чтобы не терять точность в JavaScript.
- **`users.id` — это Telegram ID**, тип `bigint`: Telegram ID не помещаются в `integer`. Отдельный суррогатный ключ не нужен.
- **`spent_at` — тип `date`**: по заданию это дата траты, время из «кофе 350» всё равно не извлечь. Порядок добавления («последнее было не 350, а 450») берётся по `created_at`.
- **Категории — фиксированный список** с `CHECK` в БД и типом `Category` в Go: свободный текст дал бы «Еда», «еда» и «продукты» как разные категории.
- **Изоляция трат — в SQL**: запросы бота содержат `AND user_id = $n`, поэтому чужая трата для пользователя неотличима от несуществующей (`404`), а проверка и изменение выполняются одним атомарным запросом. Панель передаёт «все пользователи».
- **Валидация в сервисе, ограничения в БД**: сервис возвращает понятные доменные ошибки, а `CHECK` и внешние ключи — последний рубеж, если данные придут в обход сервиса.
- **Миграции — отдельный сервис в compose**, а не внутри приложения: бинарников два (`api` и `bot`), и миграции не должны запускаться дважды.
- **Отдельные DTO в HTTP-слое**: формат API (дата `YYYY-MM-DD`, сумма строкой) не протекает в доменную модель.
- **ID пользователя в инструменты подставляет код, а не модель**: у инструментов нет параметра `user_id`, поэтому агент физически не может обратиться к чужим тратам, даже если его об этом попросить.
- **Суммы считает база (`SUM ... GROUP BY`), а не LLM**: модели ошибаются в арифметике, а выгружать в контекст сотни трат дорого. `list_expenses` ограничен 50 записями и сообщает модели, что список обрезан.
- **Даты периодов считает код**: в системный промпт подставляются сегодня, вчера, границы недели и месяца в часовом поясе семьи. Модель выбирает период, но не делает календарную арифметику.
- **Ошибки инструментов возвращаются модели** (`is_error`), а не обрывают диалог: неверная дата или «трата не найдена» превращаются в понятный ответ пользователю. Внутренние ошибки пишутся в лог, модели уходит только «internal error».
- **Память диалога — последние 10 сообщений, только текст**, на 1 час, отдельно для каждого пользователя. Вызовы инструментов и размышления модели между сообщениями не хранятся: контекст короткий и дешёвый, а старые сообщения можно отбрасывать, не нарушая требований API к истории.
- **Сообщения одного пользователя обрабатываются по очереди**, разных пользователей — параллельно: «кофе 350» и «последнее было не 350, а 450» не выполнятся одновременно.
- **Агент не зависит от провайдера LLM**: он работает через интерфейс `agent.LLM` со своими типами сообщений. Есть два адаптера: OpenAI-совместимый (покрывает OpenRouter, Cloud.ru, OpenAI, Ollama, vLLM) и Claude API через официальный SDK. Провайдер выбирается в конфиге, агент при этом не меняется.
- **Веб-панель встроена в `api`** (`go:embed`): одна команда запуска, без отдельного фронтенд-контейнера и сборки. Текст из Telegram выводится через `textContent`, а не `innerHTML` — комментарий вида `<script>` не выполнится. Суммы в панели складываются в копейках, без ошибок округления JavaScript.
- **Члены семьи вступают по ссылке-приглашению** `t.me/<бот>?start=<код>`, а не по списку Telegram ID: обычному человеку не нужно узнавать свой ID, главе семьи не нужно перезапускать бота для каждого нового члена семьи. Членство — это запись в `users`. Код сравнивается за постоянное время (`crypto/subtle`), длина не меньше 8 символов против перебора. Ограничение: чтобы исключить человека, нужно удалить его из `users`, а смена кода не отзывает уже выданный доступ.
- **Без авторизации в панели и с CORS `*`** — так в задании.
- **Одна валюта и полное удаление** (без soft delete) — для семейного учёта этого достаточно.
